# Contribution Rules

1. Use a feature branch. Do not push development work to `main` or `data`.
2. Keep one responsibility in each module.
3. Add a test for each bug fix.
4. Do not add live credentials or private configuration URIs to tests.
5. Do not add synthetic latency, throughput, uptime, or IP evidence.
6. Keep State transitions and public output deterministic.
7. Run the full test suite and the offline pipeline before you open a pull request.
8. Update the relevant document when a contract changes.
9. Do not reduce a security control without a reviewed decision record.
10. Do not force-push to the public data branch.
